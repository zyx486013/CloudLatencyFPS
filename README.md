# CloudLatencyFPS

**云电脑 / 远程串流的输入响应、画面流畅度和码率压力测试工具。**

在云端显示带黑白识别码的测试画面，在本地从串流返回的画面中读取识别码，记录点击响应、鼠标反馈和画面更新节奏。适合排查“转视角时卡顿”“高码率比低码率更卡”“画面流畅但操作拖后”等体验，也可对比不同网络、串流参数和客户端设置。

## 下载与运行

- **[下载 CloudLatencyFPS.exe（0.8.1，Windows x64）](https://github.com/zyx486013/CloudLatencyFPS/raw/refs/heads/main/CloudLatencyFPS.exe)**
- [查看完整技术说明与验证记录](docs/TECHNICAL.md)

支持 Windows 10/11 x64，便携运行。将 EXE 放在可写文件夹，双击启动；运行现成 EXE 无需安装 Python 或编译器。3D 场景需要正常的 OpenGL 显卡驱动。

**云电脑和本地电脑各放一份同版本 EXE。** 云端选择显示测试信号，本地选择自动识别器。本地程序读取屏幕画面，不需要额外连接服务器或手动同步两台机器的时钟。

## 有哪些功能

| 功能 | 用来观察什么 |
|---|---|
| 点击延迟 | 从本地按下鼠标，到返回画面的事件码变化需要多久；提供当前值、中位数和 P95 |
| 帧率测试 | 观察返回画面的更新频率和节奏 |
| 自动运动 | 匀速往返竖条，直观看停顿、跳动和更新不均匀 |
| 鼠标运动 | 黑边白色十字显示云端收到的位置；停住约 0.2 秒后再移动，测移动起始反馈 |
| FPS 转视角 | 固定准星、真实 3D 房间，支持鼠标转头、俯仰和 WASD 走动 |
| 自动 60 秒测试 | 固定动作脚本，便于重复比较不同码率 |
| 连续跟踪估计 | 对比本地水平鼠标轨迹和返回视角，估计连续操作的时间落后 |
| 码率对比 | 保留本次进程最近最多 16 轮，生成 HTML 报告和 CSV |
| 统计与趋势 | 帧间隔中位数、P95/P99、1% Low、MAD、最长间隔、长间隔次数、识别未知时间等 |
| 窗口设置 | 窗口化、紧凑跟随、F11 无边框全屏；识别码比例 20%～90%、锁定布局、识别器保持置顶 |

FPS 场景可以选择 **3D 网格房间、3D 纹理房间、高压细节（2D）、极限噪声（2D）**。两个 3D 房间另有标准 / 高压 / 极限三档，默认极限。高压和极限档加入不规则多尺度细节与交错杆件，增加转视角时的编码压力；极限档含明显走样和闪烁，适合作为合成压力测试。日常对比可先用标准或高压，再用极限放大差异。

## 第一次使用

1. **云端启动信号。** 选固定显示窗口，再选测试类型。先设置窗口大小、全屏、场景、压力和目标频率。
2. **本地打开识别器。** 保持云电脑客户端的测试画面可见。
3. **框选黑白码。** 把鼠标放到码区左上角按 `F2`，再移到右下角按 `F3`。原有四种测试框住完整 **2:1** 码；FPS 转视角框住完整 **4:1** 码组。只包含黑白格子，排除说明文字和背景。
4. 等待预览能稳定识别，然后点击本地 **开始记录**。
5. 在云电脑画面中操作或运行自动测试。结束后点击 **停止并保存**；FPS 自动测试读到结束阶段时也会自动保存。

**固定顺序：调整云端布局 → 框选本地码区 → 开始记录。** 窗口位置、大小、全屏、缩放或 DPI 改变后重新框选。可启用锁定布局，减少测量中误操作。

### 测点击与普通鼠标反馈

- **点击延迟：** 云端选择点击延迟，本地框码并开始记录。鼠标在云电脑画面内，避开程序按钮，间隔点击多次；等待每次反馈完成再进行下一次。看多次样本的中位数和 P95。云端大数字表示本次按住时长，响应延迟看本地识别器。
- **鼠标运动：** 云端选择鼠标运动，本地开始记录。鼠标停住约 0.2 秒，再在云电脑画面内移动，重复几次。十字中心对应云端收到的鼠标位置。
- **帧率 / 自动运动：** 明确选定目标频率，框码后连续记录，观察帧间隔与运动是否均匀。

### 测 FPS 转头与“跟踪”

1. 云端选择 **FPS 转视角 → 3D 纹理房间**，选择压力档位，按 `F4` 切到相对鼠标控制。
2. 点击场景捕获鼠标。左右移动控制转头，上下移动控制俯仰；`WASD` 走动，`F7` 重置。`Esc` 释放鼠标。
3. 本地框选整组 4:1 识别码并开始记录。手动捕获鼠标后，若码区位置未变，可以继续使用原选区。
4. 测起始响应时先停住约 0.2 秒再移动；测跟踪时做几秒钟 **水平左右变速、反向** 的动作。

“跟踪”表示连续操作期间，返回视角相对本地鼠标输入的时间落后。例如显示 80 ms，表示这段轨迹匹配的最佳时间偏移约为 80 ms。静止或一直匀速移动时特征较少，程序会等待更有区分度的动作。搜索范围 0～500 ms，每秒更新一次，仅匹配水平转向。

云端需要接收到相对 Raw Input。若捕获后鼠标移动而相对输入事件数一直为 0，请启用云电脑客户端的游戏鼠标 / 相对鼠标模式。自动转头可独立用于帧节奏比较。

### 比较低、高码率

1. 固定串流分辨率、编码格式、帧率、本地刷新率、场景、压力、窗口和码区比例。
2. 云端选 **FPS 转视角 → 3D 纹理房间 → 自动 60 秒**，明确设为 60 Hz 或实际测试频率；码区比例建议先用 20%～30%，以稳定识别为准。
3. 在云电脑客户端设定低码率；本地填写对应的码率标签，例如 `20` Mbps。
4. 云端按 `F7` 重跑，在初始静止阶段尽快点击本地 **开始记录**。
5. 自动动作：**静止 10 秒 → 慢转 20 秒 → 快转 20 秒 → 急停 10 秒**。结束后保留结果。
6. 改为高码率，按相同步骤测试，再降回低码率。推荐 **低 → 高 → 低，每档重复 3 轮**。
7. 点击 **码率对比** 查看 HTML，结合 P95/P99、长间隔、最长间隔、识别未知时间和云端绘制耗时比较。

码率标签由用户填写，实际码率在串流客户端调整。建议同时记录客户端显示的实际接收码率、网络丢帧、解码耗时和显示队列，以便解释差异。

## 如何减少测量误差

| 操作 | 原因与建议 |
|---|---|
| 先预热，再记录 | 等场景纹理初始化、串流画质和频率稳定后开始；切换场景或压力后重新预热 |
| 只改一个变量 | 比较码率时，其余串流、显示、输入与场景设置保持一致；手动测试也保持鼠标 DPI、回报率和客户端输入模式一致 |
| 优先用固定自动动作比较 | 自动转头每轮动作相同，减少手动速度不同带来的画面复杂度差异 |
| 明确设置目标频率 | 正式对比避免使用“自动”；当前自动档的长间隔阈值按 60 Hz 计算 |
| 匹配显示和串流频率 | 尽量让云端目标频率、串流帧率与本地刷新率匹配；本地刷新率低会限制可观察到的更新 |
| 精确框选并稳定识别 | 边缘、文字和背景会干扰解码；格子太小或压缩后糊成一片时，适当放大码区并重新框选，各轮保持同一比例 |
| 保持码区可见 | 本地识别器置顶时放在码区之外；避开通知、菜单、鼠标指针和其他窗口遮挡；保持串流窗口可见、非最小化 |
| 记录期间固定布局 | 不移动、缩放窗口，不切换全屏、DPI、场景或压力；发生变化就结束本轮并重新框选 |
| 减少系统背景负担 | 关闭无关下载、录屏和高负载程序；保持同一电源模式与连接方式，留意 CPU/GPU 占用和温度 |
| 多次重复并交替顺序 | 使用低→高→低，比较多轮中位趋势及尾部表现，降低网络随时间波动的影响 |
| 同时看识别质量和源端耗时 | 未知时间偏多先改善识别；源端自身绘制变慢时先降低场景压力或排查显卡负担 |
| 用录像做物理显示对照 | 如需观察实际屏幕反馈，可用高帧率录像同时拍到操作与返回画面 |

**测量范围：** 延迟从本地输入钩子记录到返回画面可解码为止，包含输入转发、云端处理、编码、传输、解码、呈现和本地截图采样等环节；鼠标硬件报告前的等待、显示器扫描和像素响应需通过物理方法另测。记录时目标采样周期为 2 ms，实际周期受调度与截图开销影响。使用同一环境做多轮对比，比追求小数位更有意义。

## 指标怎么看

| 指标 | 含义与使用方法 |
|---|---|
| 观察更新/s | 本地读取到不同画面序号的频率，越接近预期越好 |
| 帧间隔中位数 | 一般更新节奏；60 fps 的理想周期约 16.67 ms，120 fps 约 8.33 ms |
| P95 / P99 | 95% / 99% 的有效帧间隔不超过此值，用来查看尾部卡顿；同条件下越低越好 |
| 1% Low | 最慢 1% 有效间隔的平均值换算成每秒更新数，越高越好 |
| MAD | 帧间隔相对中位数的离散程度，越小越均匀 |
| 最长有效间隔 | 本轮可确认的最长更新等待 |
| 长间隔/分钟 | 超过目标周期 1.5 倍的间隔次数，按记录时长换算；60 Hz 时阈值约 25 ms |
| 未观察帧 | 连续识别期间跳过的源端画面序号，可能与采集、串流或本地观察过程有关 |
| 识别未知时间 | 截图失败、校验失败或遮挡导致无法确认状态的时长；先把这一项控制好再比较 |
| 起始响应 | 从静止后首次移动到返回画面反馈的时间 |
| 跟踪估计 | 连续水平输入与返回视角的时间偏移，配合变速和反向动作查看 |
| 云端绘制耗时 / CPU 提交 | 源程序绘制调用及提交的墙钟耗时，用来观察测试源自身的负担 |

实时帧节奏统计主要看最近 5 秒，FPS 对比报告看整轮有效间隔。FPS 中跨过识别失败区段的间隔单独列为未知，不进入有效帧间隔分位数和长间隔计数。画面帧号与鼠标事件号独立记录。结合串流客户端统计，可以进一步区分网络、解码、显示及源端负担。

## 记录文件与设置

文件保存在 EXE 所在目录，请使用可写文件夹：

- `CloudLatencyFPS_results_v0.8.csv`：本地测量记录，按 `run_id` 区分轮次。
- `CloudLatencyFPS_source_v0.8.csv`：源端绘制记录。
- `CloudLatencyFPS_comparison.html`：码率对比报告，每轮结束更新。

当前进程的界面对比列表最多保留 16 轮，退出后列表不恢复；CSV 和 HTML 留在磁盘。重要结果请及时复制到单独文件夹。正常停止与退出会刷新日志，直接强制结束进程可能丢失最后一部分记录。

识别码比例和置顶设置位于 `%LOCALAPPDATA%\CloudLatencyFPS\settings.ini`。码区选区和鼠标捕获状态不保存。两台机器 CSV 的 `process_time_ms` 各自属于所在进程，跨机器分析请使用事件/帧序号关联。

## 常见问题

- **一直等待识别：** 确认两端同版本、框住完整码组、黑白格清晰且无遮挡，再重新 F2/F3；FPS 码组宽高比为 4:1。
- **转头无反应：** F4 切到鼠标控制并点击捕获，查看相对输入事件数；按 Esc 可释放。
- **没有跟踪值：** 开始记录后做水平变速和反向动作，持续几秒；静止和匀速动作的匹配区分度低。
- **结果偏低或跳帧多：** 先检查本地刷新率、串流目标帧率、识别未知时间和机器负载，再看客户端统计。
- **3D 初始化失败或很慢：** 检查显卡驱动与硬件加速；可切换 2D 场景作对照。
- **无法保存：** 把 EXE 移到有写权限的文件夹再运行。

## 编译与验证

Windows：安装 Visual Studio C++ 工具与 Windows SDK，在 **x64 Native Tools Command Prompt** 中运行：

```bat
build_windows_msvc.bat
```

Linux 交叉编译：安装 LLVM-MinGW，将 `LLVM_MINGW_DIR` 指向工具链目录，再运行：

```bash
LLVM_MINGW_DIR=/path/to/llvm-mingw bash build_linux_cross.sh
```

预编译 EXE 使用 LLVM-MinGW 20260616、C++17/O2 和静态运行库。源码包含核心协议、3D 相机、压力纹理、窗口生命周期模拟与 EGL 渲染验证脚本；依赖及原有验证结果见 [技术说明](docs/TECHNICAL.md) 和 [VALIDATION.txt](VALIDATION.txt)。Windows 的 MSVC 脚本尚未实际编译验证，真实云电脑性能以使用环境实测为准。
