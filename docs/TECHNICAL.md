# CloudLatencyFPS 0.8.1

Windows 10/11 x64 便携程序。云端显示测试信号，本地识别返回画面。新增针对“FPS转视角时，高码率更卡”的GPU 3D 转视角测试；保留原来的点击延迟、帧率、自动竖条和鼠标十字。

## 0.8.1 窗口切换修复

修正最大化、全屏与还原路径中的栈空间和重入绘制问题。旧版优化后的主消息回调栈帧为 208,888 字节，即使只处理尺寸消息也会分配；嵌套窗口消息可能耗尽默认 1MiB 栈。新版将绘图入口和识别器绘图函数显式隔离，消息回调降为 288 字节、普通绘图入口 784 字节，并将 Windows 栈预留显式设为 4MiB。

重入 WM_PAINT 只安排后续一次重绘，避免绘制中再次释放/重建同一个缓冲。OpenGL 子窗口改变尺寸前先解除当前绘图绑定；调整尺寸时禁止同步擦除及旧像素复制，再重新绑定并绘制。

协议和三档压力与 0.8.0 相同，现有 ROI 在窗口尺寸/码区位置改变后仍需重新框选。优先替换云端 EXE，本地也可统一使用本版本。

## 先测试高码率卡顿

云端、本地都换成此版本。程序无需安装、Python或额外运行库，放在可写文件夹解压运行。

1. 云端启动EXE，选择固定显示窗口，在“测试”下拉框选择 **FPS 转视角**。F8也可循环到此模式。
2. 选择 **3D 纹理房间 / 极限 / 自动60秒**，频率明确选60Hz或120Hz，并与串流目标帧率一致。F11全屏。建议识别码比例20%～30%，让更多画面用于纹理运动。
3. 本地启动第二份EXE，选择自动识别器。F2/F3框住云端下方**整组4:1黑白码**，不要只框其中一个小块，不要包含上面的说明文字。
4. 本地填写“码率标签”，例如20 Mbps。它只给本轮数据加标签，不会更改云电脑客户端的码率，也不是实际接收码率。
5. 云端按F7重新开始60秒动作；在初始静止阶段，本地点“开始记录”。随后不要变更场景、目标频率、显示方式或ROI。脚本包含：静止10秒 → 慢转20秒 → 快转20秒 → 急停10秒。
6. 收到结束阶段时，本地会自动停止并保留这一轮。也可手动点“停止并保存”。报告提示是否未覆盖完整60秒。
7. 在云电脑客户端把码率改高，填新的标签，按相同顺序再测。再降回原值复测。推荐 **低→高→低，每档3轮**。
8. 每轮结束自动更新HTML报告；点击本地“码率对比”打开当前进程最近最多16轮的结果。退出程序后不恢复界面对比列表，已保存的HTML和CSV仍在。

请固定分辨率、编码格式、目标帧率、本地刷新率、场景、识别码占比及测试动作。建议预热场景后再开始记录，同时查看云电脑客户端的实际接收码率、网络丢帧/抖动、解码与显示队列指标。

常用两档是实际 3D 几何场景：70°垂直视野、透视投影、深度缓冲、近处立柱、箱子、成排横梁、远处墙面和地面。鼠标控制相机朝向，物体随距离呈现大小和遮挡变化；WASD 移动会产生近远景视差。自动测试保持相机位置固定，按相同时间脚本转头，便于比较不同码率。静止时背景不动，识别码持续更新。

0.8.0 在 3D 网格和 3D 纹理房间增加“标准 / 高压 / 极限”压力选择，默认极限。**云端与本地均需更新**，新版识别并记录压力档位。
## FPS鼠标控制

- 云端F4切换“相对鼠标”。点击场景捕获鼠标：准星固定，左右移动转头，上下移动俯仰；3D 房间中按 WASD 前后左右走动，F7 回到初始位置。高压档为32区域独立运动，极限档在转视角时切换噪声块。
- Esc先释放鼠标，再次Esc退出全屏；F11切换显示方式时也会释放。切换模式、失去焦点、最小化、调整窗口或退出时释放鼠标。
- 该模式需要云端接收到相对Raw Input。界面显示相对输入事件数。若鼠标动了但计数始终为0，请检查云电脑客户端的相对鼠标/游戏鼠标模式；仅有绝对坐标或不提供Raw Input的输入方式不适用。自动运动不依赖鼠标输入。
- 捕获后先停住约0.2秒，再开始移动，可以记录新的移动起始响应。随后做**水平左右变速和反向**，用于连续跟踪延迟估计。
- 连续跟踪只比较本地累计水平Raw Input与返回画面的展开水平视角。俯仰角会记录，但不用于该估计。允许输入比例不同；匀速、静止、轨迹相关性不够或多个候选延迟同样合适时，显示证据不足。
- 跟踪搜索范围0～500ms，步进2ms，最近约3秒，每秒更新一次。输出是估计值，不是物理绝对延迟；报告保存停止时最近一次有效估计，未有效匹配显示不适用。

F5循环切换四档场景，也可在场景下拉框选择。两个 3D 房间右侧有“标准 / 高压 / 极限”压力下拉框，F10 也可循环切换，适用于全屏。F10 切换会释放鼠标并重置场景；手动测试请重新点击场景捕获。切换时会预生成纹理并重新开始60秒动作，测试记录中不要切换。

| 档位 | 内容与用途 |
|---|---|
| 3D 网格房间 | 同一套 3D 房间和相机，使用网格贴图，作为低细节对照 |
| 3D 纹理房间（默认） | 砖墙、地砖、箱子与警示条纹；真实透视、深度与遮挡 |
| 高压细节（2D 合成） | 4096×2048缓存，细密叶片/碎石风格的合成细节铺满背景，无大片天空；32区域以不同方向和速度运动 |
| 极限噪声 | 4096×2048随机纹理缓存，32区域随视角变化切换采样位置，制造高强度时间变化；这是合成编码压力，不能代表真实游戏画质 |

3D 场景通过系统 OpenGL 绘制。标准档保留原版网格和砖墙作为对照；高压/极限档增加不规则、多尺度、高对比碎纹理，以及前后交错的细杆和横杆。新增杆件仅作视觉细节，不阻挡行走。

- 标准：4 张 256×256 纹理，常规三线性 mipmap；312 个四边形。
- 高压：4 张 1024×1024 缓存纹理，各 mip 层保留多尺度对比；最近 mip 层点采样，减少细节被平均成灰色；1,252 个四边形。
- 极限（默认）：同样 1024×1024，增加空间随机细节、色彩变化和更多细杆；使用点采样并保留远处原始细节，包含明显闪烁与走样，作为极限合成压力；3,612 个四边形。

各档纹理与几何在进入/切换时缓存并预热；每帧更新相机矩阵、准星和识别码。停止相机后纹理固定，没有逐帧随机噪声重建。场景、准星、整组识别码在同一双缓冲提交，不进行 GPU 回读。驱动支持时关闭额外垂直同步等待，由原有目标频率调度。

实际 OpenGL 画面做了同动作软件编码对照：960×600、60fps、120帧、连续慢转，libx264 veryfast/zerolatency、CRF23、YUV420P、2线程。标准网格 1,145,577 字节；高压 3,502,096 字节（约 3.06 倍）；极限 12,577,923 字节（约 10.98 倍）。这是固定质量编码的体积对比，用于检查合成场景的压缩难度；云电脑使用固定码率时，重点观察细纹理损失、块状模糊与帧节奏。
高压细节与极限噪声保留上一版的 2D 分区压力算法，运动停止时背景冻结。若 3D 初始化失败，界面显示错误，可按 F5 切换压力场景；若系统使用软件 OpenGL，底部提示安装或启用云端显卡驱动。

顶部的“CPU提交”包括源端绘制调用、窗口复制/刷新及交换缓冲的 CPU 墙钟耗时。GPU 的完整执行耗时需另外使用显卡工具观察。
## 原有功能与窗口设置

启动可选固定窗口、紧凑跟随或自动识别器。

- F8：点击延迟 → 帧率 → 自动运动 → 鼠标运动 → FPS转视角。
- F6：自动读取刷新率或30/60/90/120/144/165/240Hz。
- F11窗口/无边框全屏，不改变显示器分辨率；Esc返回窗口。跟随模式进入鼠标运动或FPS时转为固定窗口。
- 识别码比例20%～90%，受可用高度限制，保持整数像素方格。原有四种模式为8×4、2:1码；FPS为32×8、4:1码组。
- 锁定布局防止窗口移动、缩放及识别码比例/主模式改变。云端布局、位置、全屏、DPI或码区变化后重新框选。
- 鼠标运动用黑边白色十字表示收到的桌面坐标；自动运动用匀速往返竖条。
- 点击延迟的大数字是按住时长，不是本地测得的响应延迟。松开清除数字，事件码保持。
- F9复位原有模式；在FPS模式下等同F7重跑。Ctrl+Alt+F12退出信号程序。
- 识别器支持保持置顶、开始/停止、重新框选、清空统计、更多统计、CSV和码率对比。置顶后请勿遮住码区。
- F2/F3或重新框选会停止并保留已有FPS轮次。改变主测试模式也会结束本轮FPS记录。新记录保留ROI，重新开始统计。

## 结果解释

FPS模式把**实际完整绘制调用的画面序号**与**收到的鼠标事件序号**分开记录。小范围窗口重绘不推进帧号。源端日志同时记录绘制间隔与包含 GDI 刷新/复制与 OpenGL 提交/交换缓冲的 CPU 耗时；这些不是GPU扫描、游戏Present、视频编码或物理显示时刻。

FPS码组包含帧号、输入事件号、水平视角、俯仰、场景/控制/阶段/目标频率、源端绘制间隔、上一次绘制耗时，以及整组校验。每小块有CRC-8；额外13位整组校验用于降低旧/新字段混合造成的污染。校验不是绝对无误。两边均须更新到 0.8.1。码组高三位使用渲染档位标签：2=标准、3=3D高压、4=3D极限；2D 场景固定为2。对比报告显示压力档位，CSV 末尾追加 pressure_level（0标准 / 1高压 / 2极限），结果文件名使用 v0.8。切换压力会标记本轮设置变化。

| 结果 | 含义 |
|---|---|
| 观察更新/s | 本地观察到不同帧号的频率，受本地刷新、截图和识别影响 |
| P95/P99帧间隔 | 尾部帧节奏；主界面为近5秒，报告为整轮有效间隔 |
| 最长有效间隔 | 有效解码之间最长更新等待；无法识别的跨越间隔另列 |
| 长间隔/分钟 | 间隔超过目标周期1.5倍的次数，按记录时长换算 |
| 未观察帧 | 在连续可识别期间跳过的源端画面序号；不能单独断定网络丢帧 |
| 不确定间隔/识别未知时间 | 校验失败、截图失败或码区被遮挡时，不能确认画面状态 |
| 云端绘制最大耗时 | 测试程序自身CPU绘制开销线索，需要结合源端CSV |
| 起始响应/跟踪估计 | 输入到返回画面的起始反馈和连续水平跟踪时间偏移 |

识别失败跨越的间隔不进入FPS帧时间分位数、长间隔次数和未观察帧统计。观察更新率仍可能因此偏低，应同时看识别未知时间。FPS报告整轮分位数使用0.25ms直方图，超过1023.75ms合并到末桶；最长间隔保留未量化值。目标频率设“自动”时，长间隔阈值暂按60Hz，因此正式比较请明确选目标频率。实时1% Low是最慢1%有效间隔的平均值换算，不是游戏内部1% Low。

云端返回的绘制间隔、上一次绘制耗时为0.1ms编码，最大819.1ms；源端CSV保留完整精度。鼠标输入事件可能合并，事件号跳跃不作为视频丢帧。

原有四种模式沿用旧定义：点击事件反馈、计划帧槽、自动竖条、桌面鼠标移动事件。原有帧率/自动竖条的序号跳跃还可能包含源端未执行的计划槽，不能与FPS的实际绘制序号直接等同。

自动结果不包含鼠标硬件报告前等待、显示器扫描或像素响应。截图/调度/轮询引入额外时间，小数位不代表物理精度。高码率更卡可能来自网络突发、排队、解码、呈现或源端处理；本程序不会自动把它归因到某一级。120fps手机录像可作为物理显示结果的对照。

## 性能与记录文件

- 信号使用可中断的等待定时器，没有每帧忙等。
- 3D 几何和纹理在 GPU 中缓存，没有每帧全屏 CPU 纹理上传。压力档保留当前场景的 32MiB CPU 纹理缓存及分区复制；窗口绘图缓冲重复使用。
- FPS背景不先额外铺满一层底色；原有模式空闲时降低刷新，最小化不绘制。
- 原有模式固定128×64采样；FPS码组固定256×64采样。ROI放大不增加解码像素数，系统截图/缩放成本仍可能随源面积变化。
- 记录时目标采样周期2ms，非记录预览约10Hz；结果界面和滚动分位数10Hz，轨迹匹配1Hz。
- 固定容量轨迹、帧历史、日志队列；独立线程批量写CSV。队列满时计数丢弃，不阻塞等待磁盘。正常停止和退出刷新；强制结束可能丢失最后未刷新的记录。
- ROI代次检查排除重新框选后的旧截图；检测识别器遮挡码区。

本地：`CloudLatencyFPS_results_v0.8.csv`；云端：`CloudLatencyFPS_source_v0.8.csv`；对比：`CloudLatencyFPS_comparison.html`。均在EXE目录。每个CSV中的进程时间只用于该进程，不能直接相减得到跨机器单向延迟。CSV按run_id区分轮次，码率字段只是用户标签。

CSV列：`type,process_time_ms,sequence,delta,measurement,confidence,run_id,bitrate_label_mbps,scene,control,phase,input_sequence,yaw_deg,pitch_deg,source_interval_ms,source_paint_ms,tracking_latency_ms,tracking_correlation,interval_valid,pressure_level`。

- `fps_frame`：measurement为观测帧间隔ms；interval_valid=0表示跨过无法识别的时间段。
- `fps_source`：measurement为源端绘制调用间隔ms；source_paint_ms为当前完整绘制的CPU耗时。
- `fps_summary`：measurement为本轮P95，confidence列为本轮识别未知ms；摘要用于留存，完整比较解释以HTML报告为准。
- 原有type为latency/frame/auto_motion/mouse_motion/motion_latency，保持原measurement含义；新增列可为空。
- scene：0为3D网格房间、1为3D纹理房间、2高压细节、3极限噪声；control：0自动、1鼠标；phase：0静止、1慢转、2快转、3急停、4结束、5手动。
- tracking_latency_ms=-1表示匹配证据不足。confidence为黑白对比度指标，不是识别成功概率；tracking_correlation为轨迹相关系数。

识别码比例和置顶设置保存在`%LOCALAPPDATA%\CloudLatencyFPS\settings.ini`。不保存ROI或鼠标捕获状态。

## 源码与验证

- `CloudLatencyFPS.cpp`：主程序、原有协议、截图、统计、日志及窗口消息。
- `fps_model.h`：可独立测试的运动、角度、整组校验和轨迹匹配。
- `fps_world.h`：独立可测的 3D 房间、相机移动和碰撞。
- `fps_3d.inl`：OpenGL 窗口/上下文、缓存、相机、准星与同帧识别码。
- `fps_detail.h`：稳定的高对比、多尺度压力纹理像素。
- `fps_stress.h`：纹理像素、缓存尺寸和独立区域运动。
- `fps_signal.inl`：纹理缓存、FPS场景、码组和鼠标捕获生命周期。
- `fps_analyzer.inl`：FPS码组解码、统计、轨迹及对比报告。
- `fps_input.inl`：相对Raw Input处理。
- `layout.h`、`ui_controls.inl`：原有布局及窗口控件。
- `test_core.py`：提取实际函数，原生C++验证，不模拟Windows GUI。
- `test_stress.py`：提取实际分块绘制函数，验证纹理边界、完整覆盖、冻结/变化、四场景标记；加`--encode`可用FFmpeg/libx264重做同质量编码对照。需要Python3和g++，仅验证时需要。
- `test_window_lifecycle.py`：实际尺寸绑定/绘制调度函数的同步窗口消息模拟；500 次尺寸变化、失败分支、重入绘制合并，并编译 Windows x64 汇编检查回调栈帧。可传 `--toolchain /path/to/llvm-mingw --baseline /path/to/v0.8.0.zip` 对比旧版。
- `test_world.py`：实际几何、相机轴向、对角速度、碰撞与长帧限幅，使用 ASan/UBSan。
- `test_gpu_egl.py`：Linux EGL 下运行实际 OpenGL Build/Paint，检查八个视角/压力组合、静止画面一致性和精确码格。加 `--encode` 复现同动作编码对照；`--resize` 检查 Linux EGL 下 1080p/4K 与还原时表面重建、上下文重绑和实际绘制。需要系统 EGL/GL、Pillow、NumPy、g++；传 `--gl-header /path/to/GL/gl.h --output /tmp/render_check`。不模拟 Windows 窗口生命周期。
- `build_linux_cross.sh`：LLVM-MinGW交叉编译；设置LLVM_MINGW_DIR。
- `build_windows_msvc.bat`：Visual Studio x64 Native Tools命令行，需要Windows SDK；本次未用MSVC实编。

发布版使用LLVM-MinGW 20260616、C++17/O2、静态运行库。已通过严格交叉编译、Clang静态分析、65,536种合法码及所有单比特损坏、栅格与整组校验、435,798组原布局和140,580组FPS码组布局、序号回绕、记录启停、识别未知间隔排除、74ms延迟轨迹恢复与匀速歧义拒绝。

另通过实际 OpenGL 绘制的八视角/压力组合检查及 3D 几何/相机测试。Windows 下的窗口与鼠标捕获行为、云电脑兼容性和 CPU/GPU 性能仍需试运行验证。
